# Сценарий работы TaskFlow Bot

**Бот:** @TaskFlowAssistants_bot  
**База:** Airtable → Mod (`appYMRxgaAEw6cocZ`), таблица **Итерация**  
**Технологии:** aiogram 3.x · APScheduler · SQLite · Airtable REST API

---

## Участники

| Роль | Кто | Telegram |
|---|---|---|
| **Модератор** | Управляет публикацией, принимает результаты | личный чат с ботом + модераторская группа |
| **Исполнитель** | Берёт задачи, сдаёт результат | группа (реакция) + личный чат с ботом |
| **Бот** | Автоматизирует распределение | @TaskFlowAssistants_bot |

---

## Группы

| Airtable (`Группа`) | Telegram | Время (МСК) |
|---|---|---|
| ХХ 1.1 | MORNING_GROUP_ID | 09:00–16:00 |
| ХХ 1.3 | EVENING_GROUP_ID | 16:00–22:00 |
| ХХ 1.2 и остальные | — | **игнорируются ботом** |

---

## Поля таблицы Итерация

| Поле Airtable | Назначение |
|---|---|
| `Id` | Номер итерации (autoNumber) |
| `Этап` | Название задачи |
| `Для отправки` | Готовый текст для Telegram (MarkdownV2) |
| `Дата публикации` | Дата и время публикации (UTC, dateTime) |
| `Группа` | Целевая группа: ХХ 1.1 / ХХ 1.3 |
| `Статус` | Текущий статус (singleSelect) |
| `Исполнитель TG` | Telegram username исполнителя (singleLineText) |
| `Результат` | Текст результата от исполнителя |

## Статусы

```
Очередь  →  Опубликована  →  В работе  →  Завершено
                  ↓
             Ожидание  (требует одобрения модератора)
```

## Сценарий 1 — Стандартная публикация

### Шаг 1: Подготовка записи в Airtable

Менеджер создаёт запись в таблице **Итерация**:
- `Статус` = **Очередь**
- `Группа` = **ХХ 1.1** (или ХХ 1.3)
- `Дата публикации` = нужная дата/время (МСК)
- `Для отправки` = текст задачи в формате Telegram MarkdownV2

### Шаг 2: Poll Airtable (каждые 5 минут)

Бот автоматически:
1. Запрашивает все записи со статусом `Очередь`, отсортированные по `Дата публикации`
2. Для каждой проверяет: `Дата публикации` ≤ текущее время МСК
3. Если время не наступило — пропускает (проверит снова через 5 мин)
4. Если запись уже известна (есть в SQLite) — пропускает

### Шаг 3: Публикация в группу

Бот:
1. Берёт текст из поля `Для отправки` (MarkdownV2)
2. Добавляет подпись: `Поставь реакцию 👍, чтобы взять задачу`
3. Отправляет сообщение в нужную Telegram-группу
4. Сохраняет запись в SQLite: `record_id`, `chat_id`, `message_id`, время публикации
5. Обновляет `Статус` в Airtable → **Опубликована**

## Сценарий 2 — Взятие задачи исполнителем

### Шаг 1: Реакция в группе

Исполнитель ставит реакцию 👍 на сообщение с задачей в группе.

> Важно: исполнитель должен предварительно написать `/start` боту в личку,
> чтобы бот мог ему ответить.

### Шаг 2: Назначение

Бот:
1. Получает событие `message_reaction` (только если публикация через бота)
2. Находит задачу в SQLite по `chat_id` + `message_id`
3. Проверяет, что статус = `published` (задача ещё не взята)
4. Записывает в SQLite: `user_id`, `username`, статус → `assigned`
5. Создаёт запись в `pending_results` (ждём результат от этого пользователя)
6. Обновляет Airtable: `Исполнитель TG` = `@username`, `Статус` → **В работе**
7. Отправляет исполнителю в личку:
   ```
   Вы взяли задачу #42!
   Название задачи
   
   Когда выполните — отправьте мне результат в этот чат.
   /status — посмотреть статус задачи
   ```

## Сценарий 3 — Сдача результата

### Шаг 1: Отправка результата

Исполнитель пишет любое сообщение боту в личку (текст, фото, файл и т.д.).

### Шаг 2: Обработка

Бот:
1. Проверяет `pending_results` — есть ли у пользователя активная задача
2. Если нет — отвечает: «У вас нет активной задачи»
3. Если есть:
   - Обновляет Airtable: `Результат` = текст, `Статус` → **Завершено**
   - Очищает запись из `pending_results`
   - Пересылает сообщение (с медиа) в модераторскую группу с шапкой:
     ```
     ✅ Задача #42 выполнена!
     Название: ...
     Исполнитель: @username (id: ...)
     Результат: [оригинальное сообщение]
     ```
   - Отвечает исполнителю: «Результат отправлен модераторам. Спасибо!»

## Сценарий 4 — Повторная публикация (нет реакции 15 минут)

Если задача опубликована, но никто не поставил реакцию в течение **15 минут**:

1. `check_stale` (каждую минуту) находит «зависшие» задачи
2. Бот повторно публикует ту же задачу в группу с пометкой:
   ```
   🔁 Повтор #1 — задача ещё не взята
   [текст задачи]
   ```
3. Новый `message_id` сохраняется в SQLite, счётчик `retry_count` увеличивается
4. Статус в Airtable остаётся **Опубликована**
5. Процесс повторяется каждые 15 минут до взятия задачи

---

## Сценарий 5 — Задача с обязательным одобрением

Если у записи в Airtable поле `requires_approval` = `True`:

1. Бот **не публикует** задачу в группу сразу
2. Отправляет модераторам сообщение с кнопками:
   ```
   🔔 Итерация требует одобрения перед публикацией
   #42: Название задачи
   Группа: Утренняя (09:00–16:00)
   Публиковать в группу?
   
   [✅ Да, публиковать]  [❌ Нет, отложить]
   ```
3. Статус в Airtable → **Ожидание**

**Если модератор нажал «Да, публиковать»:**
- Задача публикуется в нужную группу (как в Сценарии 1, Шаг 3)

**Если модератор нажал «Нет, отложить»:**
- Статус в Airtable → (отклонено)
- Задача не публикуется

## Сценарий 6 — Управление через панель модератора

### Команды модератора

Доступны только пользователям из списка `MODERATOR_IDS`.

| Команда | Действие |
|---|---|
| `/start` | Приветствие + подсказка «Вы модератор: /панель» |
| `/панель` или `/panel` | Открыть панель управления |
| `/status` | Посмотреть свою активную задачу |

### Панель управления

```
⚙️ Панель модератора

Публикация задач: ✅ включена

[🛑 Остановить публикацию]
[🔄 Обновить]
```

**Кнопки:**
- **▶️ Включить публикацию** — разрешает боту рассылать задачи из Airtable (сохраняется в SQLite, переживает перезапуск)
- **🛑 Остановить публикацию** — приостанавливает рассылку (poll и republish пропускаются)
- **🔄 Обновить** — обновляет статус в сообщении панели

> По умолчанию при старте бота публикация **выключена**. Модератор должен явно её включить.

## TEST_MODE

Включается переменной `TEST_MODE=true` в `.env`.

| Поведение в TEST_MODE | Как работает |
|---|---|
| Задача не уходит в группу | Сообщение отправляется в PM пользователя `TEST_USER_ID` |
| Авто-назначение исполнителя | Бот сам назначает `TEST_USER_ID` исполнителем (без реакции) |
| Уведомление в личку | Бот пишет в PM: «[🧪 TEST MODE] Вы автоматически назначены...» |
| Результат модераторам | Пересылается в `MODERATOR_GROUP_ID` |
| Все сообщения с префиксом | `[🧪 TEST MODE]` в начале каждого сообщения |

## Технические детали

### Периодические задачи (APScheduler)

| Джоб | Интервал | Что делает |
|---|---|---|
| `poll_airtable` | каждые 5 мин | Запрашивает Airtable, публикует готовые задачи |
| `check_stale` | каждую 1 мин | Проверяет задачи без исполнителя >15 мин, повторяет публикацию |

Оба джоба **пропускаются**, если публикация выключена модератором.

### SQLite (data/state.db)

| Таблица | Назначение |
|---|---|
| `published_tasks` | Опубликованные задачи: record_id, chat_id, message_id, статус, retry_count |
| `pending_results` | Исполнители, которые ещё не сдали результат |
| `settings` | Глобальные настройки: `publishing_enabled` |

### Airtable API

- Чтение: `GET /v0/{baseId}/{table}?filterByFormula={Статус}="Очередь"&sort...`
- Обновление статуса: `PATCH /v0/{baseId}/{table}/{recordId}`
- Поле `Исполнитель TG` — тип `singleLineText`, пишется как `@username`
