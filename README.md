# TaskFlow Bot v2

Telegram-бот для ручной публикации задач из Airtable в Telegram-группу.

## Возможности

- **Ручное управление** — модератор загружает задачи из Airtable по кнопке
- **Публикация по кнопке** — каждая задача публикуется отдельно через inline-кнопку
- **Назначение исполнителей** — по реакции в группе (или кнопкой в TEST_MODE)
- **Сдача результатов** — через ЛС с inline-кнопками [✅ Принять] [❌ Не принимать]
- **Уведомления о простое** — если задачу не взяли за 30 минут
- **Поддержка медиа** — фото/документы/видео конвертируются в ссылки для Airtable
- **Тестовый режим** — один пользователь тестирует и как модератор, и как исполнитель

## Стек

- Python 3.11+
- aiogram 3.x
- APScheduler 3.x (только check_stale)
- aiohttp (Airtable REST API)
- asyncpg (PostgreSQL)
- redis.asyncio (Redis)
- python-dotenv

## Команды

| Команда | Описание | Доступ |
|---------|----------|--------|
| `/start` | Приветствие | Все |
| `/status` | Статус активной задачи | Исполнители |
| `/панель`, `/panel` | Панель управления | Модераторы |

### TEST_MODE команды

| Команда | Описание |
|---------|----------|
| `/test_status` | Текущее состояние всех задач и исполнителей |
| `/test_reset` | Очистка всех тестовых данных |
| `/test_skip_stale` | Принудительная проверка простоя (без ожидания 30 мин) |

## Панель модератора

```
⚙️ Панель модератора

[📥 Загрузить задачи]       → Ввести число → загрузить N задач из Airtable
[🛑 Остановить / очистить]  → Удалить все задачи из очереди
[🔄 Обновить расписание]   → Обновить поля загруженных задач из Airtable
```

## Сценарий тестирования

Всё происходит в двух окнах:
- **ЛС с ботом** → роль исполнителя
- **Группа модераторов** → публикации и уведомления

1. `/start` в ЛС
2. `/панель` → [📥 Загрузить задачи] → ввести: 2
3. Нажать [✅ Опубликовать] на задаче (появится в группе модераторов с [👤 Взять задачу (тест)])
4. Нажать [👤 Взять задачу (тест)] → в ЛС придёт подтверждение
5. Написать результат в ЛС → в группе модераторов карточка с [✅ Принять] [❌ Не принять]
6. [✅ Принять] → в ЛС "Результат принят", в Airtable статус=Завершено
7. Повторить с [❌ Не принять] → ввести причину → в ЛС "Результат не принят"
8. `/test_skip_stale` → проверить уведомление о простое
9. `/test_status` → убедиться в корректности
10. `/test_reset` → очистить данные

## Требования к группе XX1.3 (рабочая группа исполнителей)

Механизм «первый поставил реакцию — тот и взял задачу» зависит от того, как
Telegram доставляет события о реакциях. Чтобы он работал корректно:

- **Бот должен быть администратором группы** (без прав администратора
  Telegram не присылает детальные события о реакциях).
- **`allowed_updates` при запуске polling включает `message_reaction`**
  (см. `run.py`, массив `allowed_updates` — `"message_reaction"` должен
  быть в списке).
- **Тип чата и размер группы.** Для супергрупп с большим числом участников
  Telegram рассылает не `message_reaction` (событие с `user_id` того, кто
  поставил реакцию), а агрегированный `message_reaction_count` — **без
  идентификатора пользователя**. В этом случае механизм «первый поставил —
  тот и взял» молча **перестанет работать**: бот не будет знать, кто
  именно среагировал.

**Рекомендация:**

- Держите XX1.3 как **обычную группу** либо как супергруппу **небольшого
  размера** (ориентир — до ~50 активных участников; точный порог на стороне
  Telegram не задокументирован и со временем меняется).
- При росте группы переключайтесь на **альтернативный механизм взятия**:
  inline-кнопка «Взять задачу» под сообщением с задачей (аналогично
  кнопке «👤 Взять задачу (тест)» из TEST_MODE). Этот путь не зависит от
  `message_reaction` и работает в любых чатах.
